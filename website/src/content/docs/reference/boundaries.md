---
title: V1 边界与路线
description: 当前版本明确不做什么、为什么，以及可能演进的方向。
---

V1 的目标是「单实例、自托管、多站点批注」把主链路做扎实，而不是覆盖所有评论/社区能力。下面列出明确边界，避免在选型时产生错误预期。

## 当前版本

- 版本线：`v0.2.x`
- 存储：SQLite（WAL），单实例
- 部署：单个 Go 二进制 / Docker 镜像
- 前端：内嵌 SDK（Shadow DOM）+ 内嵌管理后台（Vue 3）

## 不提供

### 托管与运营

- 不提供 SaaS 托管、计费、套餐与租户运营后台。
- 不做独立管理子域名部署；管理后台固定挂在 `/admin/`。
- 没有管理操作审计日志、图表分析、导出报表。

### 账号

- 没有邮箱密码注册、找回密码、邮件通知。
- 没有 2FA / Passkey。
- 没有邮件/Webhook 通知（新批注、待审、回复）。
- 全局封禁只有超管可操作；没有更细的自定义角色。

### 内容治理

- 没有敏感词、举报、自动反垃圾、AI 审核。
- 没有文章级独立评论区；评论必须挂在批注下。
- 没有导入/导出工具；迁移需要直接操作数据库。

### 架构

- 不支持 PostgreSQL。
- 不支持多实例 / 水平扩展；限流计数在进程内。
- 不兼容旧单站点 API，不迁移旧数据。

### SDK

- 登录使用整页跳转；弹窗 + `postMessage` 留到后续版本。
- 不支持 iframe 跨文档共享选区；iframe 内需要单独初始化。
- 面向现代浏览器（ES2020+），不支持 IE。

## 为什么

- **SQLite + 单二进制**让自托管成本最低：一个文件、一个进程、一个卷。
- **管理后台内嵌**避免额外的静态站点与跨域配置。
- **评论挂在批注上**是产品定位，不是通用评论系统的替代品。
- **先发后审/先审后发**覆盖大多数博客与文档站场景；更复杂的审核流需要周边系统。

## 可能的演进方向

以下**不是承诺**，只是代码结构上已经预留或容易扩展的方向：

- 把仓储层替换为 PostgreSQL，支持多实例；
- 弹窗登录与 `postMessage`；
- 邮件/Webhook 通知；
- 审计日志与更细的角色；
- 数据导入/导出；
- 更丰富的审核策略（举报、敏感词、自动分类）。

如果你需要其中某项，可以先提 Issue 讨论场景与优先级。

## 升级注意

- 升级会在启动时自动执行数据库迁移。
- V1 不兼容旧单站点 API，也不迁移旧数据；如从更早的内部版本升级，请先在测试环境验证。
- 回滚前先备份，并确认旧版本能读新 schema。
