## 角色

| 角色 | 范围 | 能力 |
| --- | --- | --- |
| 超级管理员 | 全平台 | 所有站点、站点设置、站点管理员、全局用户封禁、OIDC 提供商、审核 |
| 站点管理员 | 被分配的站点 | 审核队列、站点封禁、OIDC 提供商；不能修改站点设置 |
| 普通用户 | 登录后的账号 | 创建/编辑/删除自己的批注与评论、标记已解决、管理自己的身份与会话 |
| 匿名读者 | 未登录 | 读取已通过的批注与评论；不能写入 |

### 权限判断

- 批注/评论的修改与删除：作者本人、站点管理员、超级管理员。
- 审核队列：站点管理员或超级管理员。
- 站点设置（Origin、审核模式、主题、状态）：仅超级管理员。
- 全局用户封禁：仅超级管理员。
- 站点封禁：该站点管理员或超级管理员。

## 审核模式

站点创建时通过 `--moderation` 指定，之后可由超级管理员修改：

| 模式 | 行为 |
| --- | --- |
| `post`（先发后审） | 新批注/评论立即可见，默认 `approved`；管理员可事后隐藏或删除 |
| `pre`（先审后发） | 新内容进入 `pending`，通过后才对普通读者可见 |

审核状态：

```text
pending ──通过──► approved
   │
   └──拒绝──► rejected
```

可见性：

```text
visible ──隐藏──► hidden ──恢复──► visible
   │
   └──删除──► deleted（软删除）
```

普通读者只能看到 `approved` + `visible` 的内容；管理员在审核上下文中可以看到全部状态。

## 审核工作台

管理后台的审核页支持：

- **筛选**：按状态（待审/已通过/已拒绝）、类型（批注/评论）与关键词；
- **服务端搜索**：匹配引用、正文、页面、作者与评论内容；
- **状态计数**：各筛选条件下的数量；
- **URL 同步**：筛选条件写入 URL，可分享或刷新保持；
- **上下文**：评论会带出所属批注的正文、引用、页面与讨论串；
- **批量操作**：通过 / 拒绝 / 隐藏 / 恢复；
- **单条处理**：查看完整讨论、封禁作者、删除内容。

### 待审角标

站点有待审内容时，管理后台对应站点与审核入口会显示角标，方便管理员快速发现积压。

## 封禁

| 类型 | 操作者 | 效果 |
| --- | --- | --- |
| 站点封禁 | 站点管理员 / 超管 | 该用户不能在**该站点**创建或修改批注/评论 |
| 全局封禁 | 超管 | 该用户无法登录，现有会话也会被拒绝 |

封禁是软操作：数据保留，解除封禁后恢复写入能力。封禁原因会记录在站点封禁列表中。

## 管理后台

`/admin/` 下的主要页面：

| 页面 | 可见角色 | 内容 |
| --- | --- | --- |
| 概览 | 管理员 | 站点、用户、内容等统计 |
| 站点 | 超管 | 创建/编辑站点、轮换 siteKey、分配管理员 |
| 站点详情 | 管理员 | 审核、封禁、OIDC 提供商（超管另可改设置） |
| 审核 | 管理员 | 待审/已审内容与批量操作 |
| 用户 | 超管 | 全局用户与封禁 |
| 账号设置 | 所有管理员 | 本地超管改密、会话管理 |

管理后台与 API 同源，挂在 `/admin/`，不需要单独部署。

## 首个超级管理员

两种方式：

1. 首次启动自动创建本地超管（默认 `admin` / `admin`，强制改密）；
2. 配置 GitHub 登录后提升：

```bash
./bin/zhupi admin promote --github-login <login>
```

生产环境建议至少提升一个 GitHub 账号，避免只依赖本地密码。
