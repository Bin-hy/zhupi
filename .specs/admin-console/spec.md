# Annotation Service 管理后台 Web UI · Spec

> 状态：草案 v0.1（等待评审）
> 范围：内嵌 `/admin` 的治理后台（Vue 3 + Element Plus）+ 最小后端补充
> 关联：多站点服务、可嵌入 SDK 已完成；博客接入已完成

## 背景

annotation-service 已经具备多站点、GitHub/站点级 OIDC、批注与评论、审核、站点管理员、
用户封禁与 OIDC 提供商管理等 REST API，并有 CLI 可用。但日常运营仍依赖 curl/CLI：

- 超管无法直观管理站点、来源、审核模式与 siteKey；
- 站点管理员无法在界面上处理待审内容、封禁用户；
- OIDC 提供商配置需要手写 JSON；
- 没有全局概览，无法快速判断待审积压与站点状态。

本子项目交付一个内嵌在 Go 服务 `/admin` 的管理后台，供超管与站点管理员使用。

## 目标

- 提供完整治理台：概览、站点、站点管理员、用户、审核、站点封禁、OIDC 提供商。
- 与现有 API 同源部署，无 CORS/Cookie 复杂度。
- 超管与站点管理员权限边界清晰，后端强制、前端隐藏越权入口。
- 管理端登录复用现有账号体系：全局 GitHub + 站点 OIDC。
- 表单校验、确认、加载/空态/错误、分页等后台基础体验完整。
- 为后续审计、统计图表、独立子域名部署留出边界，但 V1 不实现。

## 角色

- **超级管理员**：管理全部站点、用户、内容、OIDC 提供商、站点管理员。
- **站点管理员**：只管理被分配的站点：审核、封禁本站用户、配置本站 OIDC。
- **普通用户**：可以登录后台但无任何站点权限，只看到「无可管理站点」提示。

## 功能需求

### F1 管理端登录与会话

- 后台入口为 `/admin`；未登录访问任何后台路由都跳转到登录页。
- 登录页展示可用登录方式：
  - 全局 GitHub（若服务端已配置）；
  - 所有已启用的站点 OIDC 提供商（显示站点名 + 提供商名）。
- 选择后整页跳转 IdP，回调回到 `/admin` 并消费 token。
- 登录成功后可看到当前用户、角色与可管理站点；支持退出登录。
- 会话过期（401）时清理本地状态并回到登录页。
- 登录回跳只允许 `/admin` 路径，防止开放重定向。

### F2 权限与访问范围

- 超级管理员：
  - 查看/创建/编辑/停用站点；
  - 轮换 siteKey；
  - 指定/移除站点管理员；
  - 查看全局用户并全局封禁/解封；
  - 审核任意站点内容；
  - 管理任意站点 OIDC 提供商；
  - 管理任意站点封禁。
- 站点管理员：
  - 只能看到被分配的站点；
  - 可审核本站内容、封禁/解封本站用户、配置本站 OIDC；
  - 不能创建/编辑站点、不能轮换 siteKey、不能指定管理员、不能全局封禁。
- 普通用户：登录后看到「暂无可管理站点」，不展示治理菜单。
- 所有前端隐藏仅用于体验；后端必须返回 403 拒绝越权。

### F3 概览

- 超管：全站站点数、用户数、批注数、待审批注数、评论数、待审评论数。
- 站点管理员：仅统计其可管理站点。
- 展示最近待审内容列表（最多 10 条），点击可跳转审核页。
- 加载失败显示错误与重试；无数据时显示空态。

### F4 站点管理（超管）

- 站点列表：名称、展示名、siteKey（可复制/轮换）、状态、审核模式、来源、创建时间。
- 创建站点：名称、展示名、来源（可多个）、审核模式、主题色、默认语言。
- 编辑站点：展示名、来源、审核模式、主题色、默认语言、启用/停用。
- 轮换 siteKey 需要二次确认，成功后展示新 key 并提示旧 key 立即失效。
- 站点详情页至少包含：设置、管理员、OIDC 提供商、封禁、内容审核入口。

### F5 站点管理员（超管）

- 列出站点的管理员用户（ID、名称、授予时间）。
- 通过用户搜索/用户 ID 添加站点管理员。
- 移除站点管理员需要确认。
- 不能把不存在的用户设为管理员。

### F6 用户管理（超管）

- 用户列表：ID、显示名、状态、是否超管、注册时间。
- 支持按名称/ID 客户端搜索（在已加载数据范围内）。
- 全局封禁/解封用户；封禁需要确认并说明会撤销其全部会话。
- 不提供删除用户、修改超管身份（V1 留给 CLI）。

### F7 内容审核

- 选择站点（超管可选任意站点；站点管理员只能选自己的站点）。
- 状态标签：待审、已通过、已拒绝。
- 批注与评论分开展示：
  - 批注：作者、引用文本、正文、状态、时间；
  - 评论：作者、内容、所属批注、状态、时间。
- 操作：通过、拒绝、隐藏、恢复；需要确认。
- 分页使用游标 +「加载更多」，不重复、不遗漏。
- 审核完成后列表与概览计数同步刷新。

### F8 站点封禁

- 站点封禁列表：用户 ID、名称、原因、操作时间。
- 通过用户 ID/搜索添加封禁，可填写原因。
- 解除封禁需要确认。
- 站点封禁只影响该站点写操作，不影响其他站点。

### F9 OIDC 提供商管理

- 按站点列出提供商：名称、issuer、clientId、状态、更新时间。
- 新增/编辑：
  - 名称、issuer、clientId、clientSecret、scopes、允许邮箱域、启用状态；
  - 编辑时 clientSecret 留空表示保持原值；
  - 保存前提示会做 Discovery 校验。
- 删除/停用需要确认；停用后新登录不可用。
- 响应与界面均不得展示 clientSecret 明文。

### F10 后台体验与交互

- 使用 Vue 3 + Element Plus；中文界面；桌面优先，窄屏可用。
- 表单必填、长度、URL/来源格式校验；错误在字段附近展示。
- 危险操作统一二次确认；成功/失败用全局消息提示。
- 表格/列表具备加载骨架、空态、错误重试、加载更多。
- 复制 siteKey、登录 token 清理、退出登录可用。
- 支持浅色/深色（跟随系统或手动），至少不出现不可读配色。

### F11 最小后端补充

- 管理端登录：
  - 公开的登录方式列表（GitHub + 已启用 OIDC 提供商，含站点名）；
  - `/admin` 专用 GitHub / OIDC 登录入口，回跳限制在 `/admin` 路径；
  - 复用现有回调与 token fragment。
- `GET /me/sites`：当前用户可管理的站点（超管返回全部）。
- `GET /admin/overview`：按角色返回统计与最近待审。
- `GET /admin/sites/{id}/bans`：站点封禁列表。
- 所有新增接口复用现有鉴权、错误码与限流风格。

## 非功能需求

- **N1 安全**：管理接口后端强制角色校验；不回显 secret；登录回跳限制路径；
  token 仅存本地；用户内容按纯文本渲染。
- **N2 权限一致性**：前端隐藏 + 后端 403 双重保证；跨站点操作返回 403/404。
- **N3 性能**：首屏（概览）在本地环境 2s 内可用；列表每页 50 条，游标加载更多。
- **N4 可用性**：关键流程不超过 3 次点击到达（审核、封禁、站点设置）。
- **N5 兼容性**：现代常青浏览器；1366px 及以上完整布局，窄屏可操作。
- **N6 可维护性**：Vue 3 Composition API + TypeScript strict；API 客户端统一封装；
  路由守卫与角色判断集中。
- **N7 可测试性**：API/鉴权/角色判断有单测；登录、站点、审核有 Playwright E2E。
- **N8 部署**：构建产物嵌入 Go 二进制，`/admin/` 提供 SPA fallback；
  静态资源路径与 API 同源。

## 不做的事

- 不做普通用户门户或公开站点管理页。
- 不做用户删除、身份合并/解绑、超管身份编辑（留给 CLI）。
- 不做审计日志、操作历史、回滚。
- 不做图表分析、趋势统计（只做计数卡片与最近待审）。
- 不做邮件/Webhook/实时推送。
- 不做后台国际化（V1 仅中文）。
- 不做独立子域名部署（V1 只内嵌；`ADMIN_ORIGINS` 保留给未来）。
- 不做内容全文搜索或复杂筛选（V1 仅状态筛选与客户端搜索）。

## 验收标准

- **AC1 登录**：/admin 未登录跳登录页；可选择 GitHub 或 OIDC 提供商；登录回跳 /admin；
  会话过期回登录页；退出登录生效。
- **AC2 角色**：超管看到全部站点与用户；站点管理员只看到被分配站点；普通用户看到空态；
  越权操作被后端拒绝。
- **AC3 概览**：计数卡片与最近待审按角色正确；无数据/失败态可见。
- **AC4 站点**：创建/编辑/停用站点生效；来源与审核模式保存正确；siteKey 轮换后旧 key 失效。
- **AC5 管理员**：可添加/移除站点管理员；不存在用户被拒绝；列表正确。
- **AC6 用户**：超管可全局封禁/解封；封禁后该用户会话失效；站点管理员看不到全局用户管理。
- **AC7 审核**：待审/已通过/已拒绝切换正确；通过/拒绝/隐藏/恢复生效；跨页无重复遗漏；
  站点管理员只能操作本站内容。
- **AC8 封禁**：站点封禁列表正确；封禁后该用户在该站点写操作被拒绝，其他站点不受影响；
  解封后恢复。
- **AC9 OIDC**：新增/编辑/停用/删除提供商生效；secret 留空保持原值；界面与接口不回显明文；
  Discovery 失败有明确提示。
- **AC10 部署与质量**：`npm run typecheck`、单测、构建通过；Go 服务 `/admin/` 可加载；
  Playwright 主流程通过；深链刷新不 404（SPA fallback）。

## 待确认的实现假设

1. 后台与 API 同源内嵌 `/admin`，V1 不单独部署子域名。
2. 登录页公开展示所有启用站点的 OIDC 提供商名称与 issuer（自托管场景可接受）。
3. 站点管理员不能编辑站点设置、轮换 siteKey、指定管理员；这些仅超管可做。
4. 列表分页统一使用游标 +「加载更多」，不做页码分页。
5. 后台 V1 仅中文，不做多语言与图表分析。
