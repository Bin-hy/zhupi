# VitePress 站内接入打磨 · Spec

> 状态：草案 v0.1（等待评审）
> 范围：go-campus 博客的 SDK 接入体验 + SDK 少量公共 API 增补
> 关联：annotation-service（多站点服务、可嵌入 SDK、管理后台）已完成

## 背景

go-campus 博客已接入 annotation-service 的可嵌入 SDK，基本可用：
选中正文划线、登录、发布批注、刷新恢复都能工作。

但当前接入仍是「能跑」而非「原生」：

- 路由切换靠 `destroy + init`，没有使用 SDK 的 `setPage`；
- SDK 主题只跟随系统，不跟随 VitePress 自己的暗色开关；
- 只有右下角 FAB，没有顶部导航入口；
- 抽屉从页面顶部开始，会盖住 VitePress 顶栏；
- FAB 可能与页面右下角控件（回到顶部等）重叠；
- SDK 脚本/接口失败时，博客侧只有 console 警告，没有用户可见的降级提示；
- 首页/404 没有正文，仍需避免 SDK UI 出现。

本子项目只做博客接入体验与少量 SDK 公共 API，不重做 SDK UI，也不改管理后台。

## 目标

- 让划线批注在博客里像站内原生功能：顶部有入口、暗色同步、布局不打架。
- 文档页之间切换使用单实例 `setPage`，不重复创建实例。
- 首页/404 自动隐藏 SDK UI；回到文档页自动恢复。
- 失败时用户能感知（入口禁用/提示），而不是静默失效。
- 保持 Artalk、图片放大、mermaid、搜索等现有功能不受影响。

## 功能需求

### F1 单实例生命周期

- 博客首次进入文档页时创建一个 SDK 实例。
- 文档页 A → 文档页 B：调用 `setPage`，不销毁实例。
- 文档页 → 首页/404：销毁实例并移除 SDK UI。
- 首页/404 → 文档页：重新初始化。
- 路由切换后等待正文 DOM 就绪（`.vp-doc` 出现）再初始化/切换页面。
- 同一时刻最多一个实例；SPA 连续切换不叠加 UI。

### F2 顶部导航入口

- 仅在文档页显示批注入口：
  - 「批注 N」按钮：打开 SDK 抽屉；
  - 未登录：显示「登录」按钮，打开 SDK 账号/登录面板；
  - 已登录：显示头像（无头像用首字母）与名称，点击打开账号面板。
- N 为当前页面全部可见批注总数，不受「我的/已解决/待审」筛选与分页影响。
- 创建、删除、审核状态变化后 N 自动更新。
- 导航入口可键盘操作，有 aria-label；移动端不挤压 VitePress 原有导航。
- 首页/404 不显示入口。

### F3 暗色主题同步

- VitePress 暗色开关变化时，SDK 主题同步切换。
- 首次加载时按当前 VitePress 主题初始化。
- SDK 账号面板里的主题切换仍可用，但 VitePress 暗色开关是主控；下一次 VitePress 切换会覆盖。
- 亮/暗下高亮、抽屉、按钮、徽章均可读。

### F4 布局融合

- 桌面端：SDK 抽屉从 VitePress 顶栏下方开始，不遮挡导航。
- 移动端：保持底部面板/全宽，不遮挡选中区域。
- FAB 位置上移，避开 VitePress 右下角控件（如「回到顶部」）。
- SDK 浮层不遮挡 VitePress 搜索、目录、社交链接等关键交互。
- 通过 CSS 变量而不是博客侧侵入 Shadow DOM 样式。

### F5 错误与降级

- SDK 脚本加载失败、站点配置失败、服务不可达时：
  - 顶部入口显示为不可用（禁用 + 提示），不弹出重复错误；
  - SDK 自身请求错误仍通过其 Toast 提示。
- 失败后下次路由切换可重试初始化。
- 不在正文中注入错误占位，不破坏阅读。

### F6 SPA 与深链接

- 文档页切换后旧高亮清理、新页批注加载；滚动位置由 VitePress 管理，不被 SDK 强制改变。
- `#annot-<id>` 深链接在页面加载后自动定位。
- 登录回跳 token 被消费后保留当前路由与深链接。
- 快速连续切换路由时，旧页面的异步结果不得覆盖新页面（由 SDK 请求序列号保证）。

### F7 SDK 公共 API 与数据增补

- `setTheme(mode)`：外部同步主题（light/dark/auto）。
- `openDrawer()`：打开批注抽屉。
- `openAccount()`：打开账号/登录面板。
- `statechange` 事件：`{ user, annotationCount, loggedIn }`，供宿主导航响应。
- `getAnnotationCount()`：返回当前页批注总数。
- `selectRoot` 支持在 `setPage` 时重新解析选择器（VitePress 会替换 `.vp-doc` 节点）。
- 列表接口增加 `total`：当前页全部可见批注数（不受 filter/cursor 影响）。
- 新增 CSS 变量：`--annotation-drawer-top`、`--annotation-fab-bottom`、`--annotation-fab-right`，默认值保持现有行为。
- 以上均为增量能力，现有 `init({ siteKey })` 调用与事件语义不变。

### F8 样式与可访问性

- 导航入口视觉与 VitePress 顶栏一致（字号、间距、hover、focus）。
- 计数徽章对比度足够；深色下不刺眼。
- 导航按钮支持 Tab/Enter；焦点样式可见。
- 打开抽屉后焦点进入抽屉；Esc 关闭并恢复焦点（沿用 SDK）。
- 不向博客注入除高亮 mark 与 CSS 变量之外的全局样式。

### F9 测试与回归

- Playwright 覆盖：
  - 文档页导航入口显示、计数正确；
  - 打开抽屉、登录态头像；
  - 暗色切换后 SDK 主题变化；
  - 文档页 A → B 的 setPage（无重复实例、旧高亮清除）；
  - 首页隐藏入口、返回文档页恢复；
  - 移动端导航与抽屉布局。
- SDK 单测覆盖新增 API 与 total 状态。
- 博客构建、Artalk、图片放大、mermaid 不受影响。

## 非功能需求

- **N1 无重复实例**：同一页面会话最多一个 SDK 实例；脚本只加载一次。
- **N2 性能**：导航入口渲染不阻塞首屏；路由切换不重复拉取站点配置（SDK 内缓存）。
- **N3 兼容性**：桌面与移动端主流浏览器；VitePress 默认亮/暗主题。
- **N4 可维护性**：博客侧接入集中在一个 bridge 模块与一个导航组件；SDK 增补保持向后兼容。
- **N5 安全**：token 仍由 SDK 管理；导航不展示 token；不新增全局敏感配置。
- **N6 回归**：Artalk 评论、Viewer.js、mermaid 放大、搜索、侧边栏行为不变。

## 不做的事

- 不重做 SDK UI 或批注交互。
- 不改管理后台。
- 不修改博客正文内容。
- 不新增批注功能（富文本、通知、搜索等）。
- 不做博客多语言切换（保持中文）。
- 不引入 Element Plus 或其他 UI 框架到博客。
- 不做自定义顶部栏替代 VitePress 导航。

## 验收标准

- **AC1 导航入口**：文档页顶部出现「批注 N」与登录/头像；首页/404 不出现。
- **AC2 计数**：N 等于页面全部可见批注数；切换筛选/分页不改变 N；创建/删除后 N 更新。
- **AC3 登录态**：未登录显示登录按钮并可打开登录面板；登录后显示头像/名称；退出后恢复。
- **AC4 暗色**：切换 VitePress 暗色开关，SDK 高亮/抽屉/按钮同步变化。
- **AC5 SPA**：文档页 A → B 使用 setPage，无重复实例；旧高亮清除；快速切换不串页。
- **AC6 布局**：桌面抽屉不遮挡顶栏；FAB 不遮挡回到顶部；移动端布局可用。
- **AC7 降级**：SDK 脚本/站点配置失败时入口禁用并有提示；恢复后重试成功。
- **AC8 深链接**：`#annot-<id>` 打开后自动定位；登录回跳保留路由与深链接。
- **AC9 回归**：博客构建通过；Artalk、图片放大、mermaid、搜索正常。
- **AC10 兼容性**：现有 `init({ siteKey })` 与 SDK 事件不破坏；SDK/博客单测与 E2E 通过。

## 待确认的实现假设

1. 顶部入口只在文档页显示，首页/404 隐藏。
2. 计数口径为「当前页全部可见批注总数」，需要列表接口新增 `total`。
3. VitePress 暗色开关为主控；SDK 内部主题切换仍保留，但会被下一次 VitePress 切换覆盖。
4. 桌面端抽屉从 VitePress 顶栏下方开始；移动端仍为底部面板。
5. FAB 默认上移到 `bottom: 80px` 左右，具体值按实际布局微调。
