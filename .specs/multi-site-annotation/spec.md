# Annotation Service 多站点划线批注产品 · Spec

> 状态：草案 v0.1（等待评审）
> 范围：V1（服务端 + 可嵌入 SDK + 管理 API/CLI）
> 代码位置：`annotation-service/`

## 背景

当前 `annotation-service` 是 GoCampus 博客的配套服务：只有一个隐式站点，所有批注按 `pageKey` 存放，登录方式是单个 GitHub OAuth App，前端能力直接写死在 VitePress 主题里。

现在要把它变成一个**可独立交付的产品**：

- 一个部署实例可以托管多个站点（类似 Artalk 的集中管理）；
- 每个站点有自己的公开站点标识、允许来源、审核策略与登录方式；
- 任意 Web 前端通过一行脚本接入，即可获得选中文字、划线高亮、批注与评论能力；
- 支持 GitHub 登录与站点级 OIDC 登录，首次登录自动建号；
- 部署者（超管）管理站点与管理员，站点管理员管理本站内容与用户；
- 数据按站点严格隔离，公开可读、登录后写。

现有单站点 API 与前端实现不再兼容，作为重写参考，不做数据迁移。

## 目标

- 一个部署实例支持多站点、多前端接入，站点间数据与权限严格隔离。
- 提供一个开箱即用的可嵌入 JS SDK，接入方无需理解锚点算法与 UI 细节。
- 提供 GitHub（部署级）与 OIDC（站点级）登录，支持多身份绑定。
- 提供超管 / 站点管理员两级治理能力，覆盖内容审核、用户封禁与站点配置。
- 保持自托管友好：单二进制、SQLite、Docker 一键部署。
- 为后续管理后台 Web、PostgreSQL、通知与风控预留清晰边界，但 V1 不实现。

## 角色

- **部署者 / 超级管理员**：初始化服务、创建站点、指定站点管理员、管理全局用户。
- **站点管理员**：管理本站点的批注与评论、审核、封禁本站用户、配置本站 OIDC。
- **终端用户**：在任意接入站点登录、划线、批注、回复。
- **接入方开发者**：在自有 Web 前端引入 SDK、初始化、处理路由切换与事件。

## 功能需求

### F1 站点管理

- 超级管理员可创建、编辑、停用站点。
- 每个站点至少包含：名称、公开站点标识（siteKey）、允许来源域名列表、启用状态、审核模式（先发后审 / 先审后发）、品牌信息（显示名、主题色、默认语言）。
- siteKey 可重置；重置后旧 siteKey 立即失效。
- 停用站点后，SDK 的读写请求返回明确的「站点已停用」错误。
- 站点数据只能由超级管理员或该站点的管理员访问。

### F2 站点隔离与来源校验

- 所有批注、评论、页面聚合、审核记录、站点管理员关系、OIDC 提供商配置都必须归属于某个站点。
- 所有面向站点的读写请求必须携带 siteKey；服务端校验请求来源（Origin/Referer）属于该站点允许的来源列表。
- 跨站点读取、修改、删除必须被拒绝，且不泄露另一站点的数据是否存在。
- 用户账号是全局的；站点的封禁、管理员身份与内容权限只在对应站点内生效。

### F3 可嵌入 JS SDK

- 接入方通过一段脚本和一次初始化即可启用：
  - 必须提供 siteKey；
  - 可选提供 pageKey、pageTitle、语言、主题、容器与回调。
- SDK 初始化后自动从服务端获取站点配置（品牌、启用状态、可用登录方式），不把站点密钥写进 SDK。
- SDK 提供完整 UI：
  - 选中正文文字后出现「批注」入口；
  - 批注编辑、发布；
  - 页面加载时还原高亮；
  - 批注列表/侧栏、回复、标记解决；
  - 登录、退出与登录方式选择。
- SDK 的 UI 必须与宿主页面样式隔离，不污染宿主全局样式；支持浅色/深色。
- SDK 支持 SPA：提供页面切换通知能力，切换后重新加载该页批注并清理旧高亮；支持销毁实例。
- SDK 至少提供 ready、登录状态变化、批注创建成功、错误四类事件。
- SDK 不依赖任何前端框架，支持 ESM 与可直接 `<script>` 引入两种分发形式。

### F4 批注与文本锚定

- 创建批注时必须携带文本锚点：精确文本、前后文、可选字符偏移与所在章节标题。
- 批注归属「站点 + 页面」；同一页面允许多条批注，不要求互斥。
- 页面加载时按锚点重新定位并高亮；正文小幅修改后应仍能定位；无法定位时标记为「原文已变更」，不得静默丢失。
- 批注状态至少包含：开放、已解决、已隐藏/已删除（用于审核与作者删除）。
- 作者可标记解决/重新打开；作者可删除自己的批注；站点管理员可隐藏或删除任意本站批注。
- 代码块、图表、公式等区域不参与划词。

### F5 批注评论

- 每条批注下可有多条评论，支持回复。
- 评论作者可删除自己的评论；站点管理员可隐藏或删除本站任意评论。
- 评论与批注一样受站点隔离与审核策略约束。
- 公开读取时按时间顺序返回可见评论；被隐藏/拒绝的内容不返回。

### F6 登录与账号

- 部署级提供一个全局 GitHub OAuth 应用，所有启用站点均可使用 GitHub 登录。
- 每个站点可独立配置一个或多个 OIDC 登录提供商（见 F7）。
- 首次通过任一登录方式成功认证时自动创建全局账号，无需单独注册。
- 账号可绑定多个登录身份（GitHub、不同站点的 OIDC）；默认**不按邮箱自动合并**，绑定与解绑必须是已登录用户的显式操作。
- 登录成功后签发会话凭证；会话可过期、可主动退出；服务端不存储明文凭证。
- 用户可查看自己的登录身份与活跃会话，并可撤销指定会话或「退出所有设备」。
- 封禁用户后其现有会话立即失效（全局封禁）或在该站点失效（站点封禁）。
- 公开可读：未登录用户可查看公开的批注与评论；创建批注/评论必须登录。
- 用户可查看并管理自己的身份绑定；管理员可封禁用户（站点级封禁与全局封禁两级）。

### F7 站点级 OIDC 配置

- 站点管理员或超级管理员可为站点新增、编辑、启用/停用 OIDC 提供商。
- 提供商配置至少包含：显示名、issuer、clientId、clientSecret、scopes、可选允许邮箱域、启用状态。
- clientSecret 必须加密存储，任何读取接口都不得返回明文。
- 登录流程必须校验 state 与 nonce，并使用授权码 + PKCE。
- 支持 OIDC Discovery（从 issuer 拉取授权、令牌、用户信息端点）。
- 同一站点可同时启用多个提供商；SDK 登录界面按站点配置展示。
- 删除或停用提供商后，新登录立即不可用；已签发的会话按策略保留或失效。

### F8 管理与治理

- 超级管理员能力：
  - 站点增删改查、启停、siteKey 重置；
  - 指定/撤销站点管理员；
  - 全局用户列表、封禁/解封、查看身份绑定；
  - 查看任意站点的内容与审核状态。
- 站点管理员能力：
  - 本站点内容审核、隐藏、删除；
  - 本站点用户封禁/解封；
  - 本站点 OIDC 配置管理。
- 提供 CLI 或一次性初始化能力：创建首个超级管理员、创建站点、指定站点管理员。
- V1 的管理能力通过 REST API 与 CLI/脚本提供，**不提供管理后台 Web UI**。

### F9 审核策略

- 每个站点可选择两种审核模式：
  - 先发后审：新批注/评论默认公开可见；
  - 先审后发：新批注/评论默认待审，仅作者与管理员可见。
- 内容状态至少包含：待审、通过、拒绝、隐藏。
- 管理员可通过/拒绝待审内容；拒绝后对公开读取不可见；作者仍可看到自己的内容状态。
- 审核粒度覆盖顶层批注与其评论。

### F10 页面标识与多前端

- 页面由「站点 + pageKey」唯一确定；SDK 未显式提供 pageKey 时使用当前路径。
- SDK 允许接入方自定义 pageKey（例如文档 slug），同一站点的不同前端可复用同一 pageKey 聚合批注。
- pageTitle 可选；用于管理端展示，不参与隔离。
- 同一站点可被多个域名/多个前端接入，只要域名在允许来源列表中。

### F11 API 约定

- 对外 API 统一使用 `/api/v1` 前缀，不保留旧单站点接口。
- 所有站点级接口必须携带 siteKey，并经过来源校验。
- 错误响应统一包含机器可读错误码与人类可读信息；不得在错误中泄露跨站点资源是否存在。
- 列表接口必须分页；公开读取默认只返回可见内容。
- 写接口按 IP 与用户维度限流。
- CORS 按站点允许来源精确放行；管理 API 仅对受信任来源/命令行开放。

### F12 运维与数据

- 服务以单二进制运行，使用 SQLite（WAL 模式）；所有 SQL 收敛在仓储层，便于未来替换 PostgreSQL。
- 提供数据库迁移机制与版本记录，升级不丢数据。
- 提供健康检查、结构化日志、优雅退出。
- 提供 Dockerfile、Compose 与反向代理部署示例。
- 提供备份/恢复说明；站点数据可按站点导出（V1 至少支持数据库级备份）。

## 非功能需求

- **N1 安全**：来源白名单、密钥加密存储、会话凭证只存哈希、限流、输入长度限制、纯文本渲染防 XSS、管理操作鉴权。
- **N2 隔离**：任何站点级查询都必须带站点条件；必须有自动化测试证明跨站点不可见、不可改。
- **N3 性能**：单页 200 条批注以内，公开读取接口 P95 低于 300ms（本地 SQLite 基准）；SDK 初始化不阻塞宿主首屏。
- **N4 可靠性**：数据库迁移可重复执行；服务重启后会话与数据可用；备份恢复流程可演练。
- **N5 兼容性**：SDK 支持现代常青浏览器；ESM 与 IIFE 两种引入方式；不依赖框架运行时。
- **N6 可运维性**：全部配置通过环境变量/配置文件注入；日志不输出密钥与明文凭证。
- **N7 可扩展性**：认证提供商、存储实现、SDK UI 主题均以可替换边界设计，但 V1 不实现多余实现。
- **N8 可用性**：SDK UI 支持键盘操作与基本无障碍对比度；默认中文，预留英文文案。

## 不做的事（V1）

- 不做管理后台 Web UI（只有 API + CLI）。
- 不做邮箱 + 密码注册、找回密码、邮件验证。
- 不做邮件通知、Webhook、实时协作/在线状态。
- 不做敏感词库、举报、自动反垃圾、验证码。
- 不做 PostgreSQL/多实例部署（只保留仓储抽象）。
- 不做移动端原生 SDK。
- 不兼容旧单站点 API，不迁移旧数据。
- 不做批注导出、第三方平台集成、离线模式。
- 不做站点级自定义域名与完整白标（只做来源白名单与基础品牌色）。

## 验收标准

- **AC1 多站点**：超管创建站点 A、B；分别用各自 siteKey 与来源访问，批注/评论互不可见；站点停用后写入被拒绝。
- **AC2 来源校验**：使用站点 A 的 siteKey 但从非白名单 Origin 请求，读写均被拒绝；白名单 Origin 正常。
- **AC3 SDK 接入**：在一个普通 HTML 页面与 VitePress 页面分别引入 SDK，均可完成选中文字、发布批注、刷新后恢复高亮；宿主页面全局样式不被污染。
- **AC4 锚点**：正文改动 1–2 个字后刷新仍能定位；大段删除后显示「原文已变更」而非静默丢失。
- **AC5 评论**：登录用户可回复；作者可删除自己的评论；站点管理员可隐藏任意评论；公开读取看不到隐藏内容。
- **AC6 登录**：GitHub 全局登录可用；站点 A 与站点 B 分别配置不同 OIDC，均可完成首次自动建号登录；同一用户可手动绑定 GitHub 与 OIDC 身份；未绑定时不会按邮箱自动合并。
- **AC7 OIDC 安全**：站点 OIDC 登录校验 state/nonce/PKCE；clientSecret 在数据库加密存储，API 不返回明文；停用提供商后新登录失败。
- **AC7b 会话管理**：用户可查看并撤销自己的活跃会话；撤销后旧凭证立即失效；封禁用户后其对应会话立即失效。
- **AC8 角色**：站点管理员只能操作本站内容与用户；跨站点管理请求返回拒绝；超级管理员可管理全部站点。
- **AC9 审核**：站点切换到「先审后发」后，新批注/评论默认仅作者与管理员可见；管理员通过后公开可见，拒绝后公开不可见。
- **AC10 页面聚合**：同一站点两个不同前端使用同一 pageKey 时看到同一批批注；使用不同 pageKey 时互相隔离。
- **AC11 API 与错误**：所有站点接口要求 siteKey；统一错误码；分页生效；限流触发时返回可识别错误。
- **AC12 运维**：`go test ./...` 通过；Docker 镜像可构建并启动；`/healthz` 正常；数据库迁移可重复执行；备份恢复后数据一致。

## 待确认的实现假设（评审时请确认）

1. V1 管理能力只提供 API + CLI，管理后台 Web 留到 V2。
2. 审核同时覆盖「批注」与「评论」；待审内容对公开读取不可见。
3. 站点管理员由超级管理员指定；站点管理员不能自行新增管理员（避免权限扩散）。
4. 全局 GitHub OAuth App 与站点级 OIDC 的 clientSecret 均由服务端环境变量/加密存储管理。
5. 现有 VitePress 主题中的划线实现改为接入 SDK，删除内置的手写批注层。
