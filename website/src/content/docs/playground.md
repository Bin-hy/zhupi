## 怎么试

1. **选中**下面任意一段文字，点击浮出的「批注」。
2. 首次发布需要 **GitHub 登录**；登录后会回到当前页面，不会丢失阅读位置。
3. 写下你的想法并发布，然后 **刷新页面**，划线应该仍然存在。
4. 点击右下角的「批注」按钮，可以查看当前页面的全部批注、回复、解决或删除自己的内容。
5. 试试抽屉里的「我的」「已解决」「待审」筛选，以及搜索和排序。

> 只想看看效果也可以：不登录同样能浏览公开批注。

## 测试正文

### 讨论应该贴着原文

传统评论区把讨论放在文章底部，读者需要反复描述「我说的是哪一段」。朱批把讨论单位缩小到一段文字、一个概念或一行代码，让批注和上下文始终待在一起。

你可以选中这句话，留下第一条测试批注。

### 一个具体的例子

假设文档里写着：「令牌只保存 SHA-256 哈希，不会以明文落库。」读者可以直接选中这句话提问：客户端令牌是如何保存的？服务端如何校验？回答也会挂在同一段引用下面，而不是漂到页面底部。

这种讨论方式适合教程精读、文档纠错、代码审阅和论文阅读，也适合知识库里那些需要反复澄清的概念。

### 原文变化后还能找到吗

朱批使用 W3C `TextQuoteSelector` 保存引用文本和前后文。正文只改了几个字时，SDK 会尝试重新定位高亮；如果改动太大导致锚点失效，批注会显示「原文已变更」，作者或管理员可以手动重新选区。

### 代码块是故意排除的

下面这段代码不会被纳入划线范围，避免用户误选代码片段后产生难以恢复的锚点：

```ts
const instance = ZhupiSDK.init({
  siteKey: 'YOUR_SITE_KEY',
  selectRoot: 'article',
})
```

## 这个测试渠道用来做什么

- 验证登录、创建批注、回复、解决和删除的完整体验；
- 观察桌面端、窄屏和暗色主题下的实际界面；
- 收集真实用户对划词、抽屉和评论交互的反馈。
