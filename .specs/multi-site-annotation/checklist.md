## B. 多站点、来源与隔离

- [ ] 超管可创建站点并生成公开 siteKey（验证：CLI 创建后返回 siteKey，DB 中存在对应站点）
- [ ] 站点名重复被拒绝（验证：用同名创建第二个站点返回冲突错误）
- [ ] 站点可由 siteKey 解析（验证：`GET /site-config` 携带正确 siteKey 返回该站点品牌信息）
- [ ] 非白名单 Origin 被拒绝（验证：用站点 A 的 siteKey + 站点 B 的 Origin 请求，读写均 403）
- [ ] 无 Origin 的请求默认被拒绝（验证：不带 Origin 请求站点级接口返回 403；测试模式开关可放行）
- [ ] 停用站点后读写被拒绝（验证：停用后请求返回明确的「站点已停用」错误）
- [ ] siteKey 轮换后旧 key 立即失效（验证：轮换后旧 key 请求 403，新 key 正常）
- [ ] 站点 A 的批注不会出现在站点 B（验证：两个站点各自创建批注，互相查询均不可见）
- [ ] 同一站点不同 pageKey 互相隔离（验证：两个页面各自批注，互不混入）
- [ ] 同一站点同一 pageKey 的不同前端看到同一批数据（验证：两个 Origin 都加入白名单后读取同一 pageKey，结果一致）
- [ ] 跨站点按 ID 直接访问被拒绝（验证：用站点 A 的 siteKey 请求站点 B 的批注/评论 ID，返回 404）
- [ ] 跨站点修改/删除被拒绝（验证：同上，PATCH/DELETE 返回 404 或 403）

## C. 登录、账号与会话

- [ ] GitHub 二次登录复用同一账号（验证：同一 GitHub 用户再次登录，user 数量不增加）
- [ ] 站点 A 与站点 B 可分别使用不同 OIDC 提供商登录（验证：两个假 IdP 各自完成授权码流程）
- [ ] OIDC 首次登录自动建号（验证：登录后生成对应 identity，siteID 正确）
- [ ] 默认不按邮箱自动合并（验证：两个提供商返回同一邮箱，仍生成两个 user）
- [ ] 已登录用户可手动绑定新身份（验证：绑定后 `/me/identities` 多一条记录）
- [ ] 绑定已被他人占用的身份被拒绝（验证：返回 409，不修改归属）
- [ ] 不能解绑最后一个身份（验证：删除唯一身份返回 400/409，仍有登录方式）
- [ ] 绑定回调失败时不影响原账号（验证：伪造/过期 state 返回错误，身份列表不变）
- [ ] 会话可列出并撤销（验证：`GET /me/sessions` 可见；`DELETE /me/sessions/{id}` 后旧 token 请求 401）
- [ ] 退出所有设备生效（验证：`DELETE /me/sessions` 后旧 token 全部 401）
- [ ] 会话过期后失效（验证：将过期时间调到过去，请求返回 401）
- [ ] 全局封禁用户后其会话立即失效（验证：封禁后原 token 请求 401）
- [ ] 站点封禁只影响该站点（验证：站点 A 封禁后 A 页面写请求 403，站点 B 仍可写）
- [ ] 封禁用户的公开读取不受影响（验证：站点封禁用户未登录/匿名读取 A 的公开批注仍成功）
- [ ] `SUPERADMIN_GITHUB_LOGINS` 命中时自动成为超管（验证：该 GitHub 登录后 `is_superadmin=true`）
- [ ] CLI 可将普通用户提升为超管（验证：`admin promote` 后管理接口可访问）
- [ ] OIDC 登录校验 state/nonce/PKCE（验证：篡改 state、缺失 nonce、错误 code_verifier 均被拒绝）
- [ ] OIDC clientSecret 加密存储（验证：直接查 DB 为密文；API 响应无明文）
- [ ] 更新 OIDC 提供商时不回传/不要求明文（验证：空 secret 更新后原 secret 仍可用）
- [ ] 停用 OIDC 提供商后新登录失败（验证：站点登录方式列表不再包含，直接调用 start 返回错误）

## I. 端到端场景

- [ ] 场景 1：两站点隔离
  - 超管创建站点 A、B，分别配置不同 Origin；
  - 站点 A 登录并发布批注；
  - 站点 B 页面完全看不到 A 的批注；
  - 用 A 的 siteKey + B 的 Origin 请求被拒绝。
- [ ] 场景 2：完整登录与绑定
  - 用户通过 GitHub 首次登录 → 自动建号；
  - 在站点 A 绑定 OIDC 身份 → 身份列表新增；
  - 解绑 GitHub 后仍可用 OIDC 登录；
  - 尝试解绑最后一个身份失败。
- [ ] 场景 3：审核闭环
  - 站点切到「先审后发」；
  - 用户 A 发布批注 → 用户 B 看不到；
  - 管理员通过 → 用户 B 可见；
  - 用户 A 再发一条 → 管理员拒绝 → 用户 B 不可见，A 可见 rejected。
- [ ] 场景 4：SPA 页面切换
  - 页面 P1 创建批注；
  - `setPage(P2)` 后 P1 高亮消失、P2 显示自己的批注；
  - 返回 P1 后原批注恢复。
- [ ] 场景 5：锚点漂移
  - 创建批注后修改正文 1–2 个字 → 仍高亮；
  - 删除整段 → 显示「原文已变更」；
  - 恢复正文 → 再次高亮。
- [ ] 场景 6：封禁
  - 站点管理员封禁用户 A → A 在该站点写请求 403；
  - A 在站点 B 仍可写；
  - 超管全局封禁 A → A 所有会话失效，任何站点需身份的请求 401。
- [ ] 场景 7：SDK 自托管
  - 空环境构建镜像并启动；
  - 打开 plain-html 示例，脚本从服务加载；
  - 完成登录、划线、发布、刷新恢复。
