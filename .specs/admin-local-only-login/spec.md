# 管理后台仅本地账号密码登录 · Spec

> 状态：已确认（v1.0）
> 范围：管理后台登录收敛、多管理员本地账号、会话来源管控、身份绑定、移除外部直登与自动超管
> 关联：`.specs/local-admin-login`（本地超管登录）、`.specs/admin-console`（管理后台）

## 背景

- 后台目前有两类入口：本地超管账号密码，以及 GitHub / 站点 OIDC 直接登录。管理 API
  只校验会话有效性和角色，不校验会话来源；站点访客通过 OIDC/GitHub 登录拿到的
  Bearer 会话，只要对应用户拥有超管或站点管理员角色，也能调用管理 API。
- `SUPERADMIN_GITHUB_LOGINS` 会在任意 GitHub 登录（包括站点访客登录）时自动授予超管，
  形成一条绕过本地登录的提权通道。
- 本地凭据目前只服务单个超管：没有后台建号、重置他人密码、多管理员管理的入口；
  站点管理员依赖 OIDC 直登后台。
- 站点访客侧本次保持不变：普通读者仍通过站点 OIDC / 全局 GitHub 登录后批注。

## 目标

- 管理后台只接受内置账号密码登录；GitHub/站点 OIDC 不再作为后台登录方式。
- 后台访问控制在服务端按会话来源强制，而不只是隐藏登录按钮。
- 超管可在后台新建管理员账号，也可为已有用户开通本地密码；账号可具备超管或
  站点管理员角色。
- 管理员登录后可在账号设置页绑定/解绑 GitHub 与站点 OIDC 身份，仅用于身份关联
  与审计，不参与后台登录。
- 移除 GitHub 自动超管通道，避免通过访客登录绕过本地认证获得管理权限。
- 升级后旧的外部登录会话不能再访问管理 API，但站点访客侧会话与功能不受影响。

## 功能需求

### F1 后台登录入口收敛

- 后台登录页只提供「用户名 + 密码」表单，不再展示或触发 GitHub / 站点 OIDC 登录。
- 服务端不再提供后台 GitHub / 站点 OIDC 登录流程；即使直接访问旧地址也不可用。
- 登录失败统一提示「用户名或密码错误」，不区分账号不存在与密码错误；被封禁账号
  提示封禁；超限返回限流错误。
- 登录成功建立普通会话，复用现有有效期与登出机制。

### F2 会话来源与后台访问控制

- 每个会话记录登录来源：本地密码、GitHub、站点 OIDC、调试登录。
- 所有管理 API 只接受「本地密码登录」建立的会话；其他来源的会话即使有效、即使
  对应用户拥有超管或站点管理员角色，也一律拒绝（403）。
- 站点公共接口与访客接口不受影响，仍接受任意有效会话。
- 升级前建立的旧会话视为非本地来源，不能再访问管理 API；不批量吊销，管理员重新
  用本地密码登录即可恢复后台访问。
- 角色授权规则不变：超管拥有全部权限，站点管理员仅限被授予的站点；强制改密拦截
  规则沿用现有行为。

### F3 多管理员本地账号

- 新增仅超管可用的管理员账号管理能力：
  - **新建管理员**：填写用户名、显示名、初始密码（可手动指定，也可由系统生成并
    只展示一次）、角色（超级管理员，或站点管理员并选择站点）。
  - **为已有用户开通本地密码**：从现有用户中选择一人，设置用户名与初始密码；
    保留其历史批注、审核记录与已绑定身份。
  - **重置密码**：超管可为其他管理员重置密码（手动指定或系统生成并只展示一次），
    重置后立即吊销该用户全部会话，下次登录强制改密。
  - **授予/撤销超管角色**：至少保留一个可登录的超级管理员；不能撤销自己的最后
    一个超管身份，也不能封禁最后一个可登录的超管。
- 同一用户最多一个本地账号；用户名不区分大小写唯一，长度 3–32 字符，仅允许
  字母、数字、`.`、`_`、`-`。
- 密码策略沿用现有规则：至少 8 个字符、最多 72 字节，使用不可逆哈希存储，任何
  接口与日志不返回明文或哈希。
- 授予超管角色时，目标用户必须已开通本地密码；站点管理员列表中对未开通本地密码
  的用户给出明确标注，并提供「开通本地密码」入口。
- 账号停用沿用全局封禁：封禁后不能登录，现有会话立即失效。

### F4 首次登录强制改密

- 由超管新建、为已有用户开通、或重置密码产生的账号，标记为「首次登录必须修改密码」。
- 该状态下只能访问账号相关接口，其余管理 API 返回「必须修改密码」错误；管理后台
  强制跳转账号设置页。
- 改密成功后清除标记，并吊销除当前会话外的其他会话。
- 环境变量引导创建的超管账号（默认 `admin` / `admin`）行为保持不变。

### F5 身份绑定与解绑

- 管理员在账号设置页可查看已绑定身份，并绑定 GitHub（服务端已配置时）或任意已启用
  的站点 OIDC 提供商。
- 绑定复用现有 OAuth/OIDC 流程，但只建立身份关联：不创建新用户、不创建本地账号、
  不签发登录会话，绑定后也不能用于后台登录。
- 绑定一个已属于其他用户的身份时拒绝并提示冲突；本期不做账号合并或身份转移。
- 可解绑身份；拥有本地密码的账号允许解绑全部身份；没有本地密码的访客仍要求至少
  保留一个登录身份。
- 绑定成功回到账号设置页并提示结果；失败也回到账号设置页并显示原因，不展示原始
  错误页。

### F6 移除外部直登与自动超管

- 移除 `SUPERADMIN_GITHUB_LOGINS` 自动提升逻辑；GitHub 登录不再改变任何用户的
  超管角色。
- 移除后台 GitHub / 站点 OIDC 直登路由与登录页入口。
- 移除按 GitHub 登录名提升超管的 CLI 能力；按用户授予超管的能力保留，并新增对应
  后台操作。
- 既有超管/站点管理员角色不自动撤销，但其旧外部会话不能访问管理 API（见 F2）。

### F7 站点访客侧保持不变

- SDK 登录仍只提供站点 OIDC / 全局 GitHub；后台本地账号不能用于站点访客登录，
  SDK 不出现密码登录。
- 站点角色、批注、审核、封禁的数据模型与权限规则不变。
- 本地管理员若要以访客身份在站点上批注，需要绑定该站点对应的 OIDC 身份。

### F8 升级与 CLI

- CLI 重置密码命令支持任意本地管理员账号，不再只针对单个超管。
- 升级后，原先仅靠 GitHub/站点 OIDC 登录后台的管理员会被拒绝进入后台；超管可通过
  后台或 CLI 为其开通本地密码后恢复。
- 数据库变更为增量迁移，不破坏现有用户、身份、批注与站点数据。

## 非功能需求

### N1 安全

- 后台访问控制以服务端为准：会话来源在登录时确定，客户端不可伪造或篡改；非本地
  来源会话访问管理 API 一律拒绝。
- 登录失败对不存在账号与密码错误返回同一错误并执行等价耗时校验；按 IP 限流沿用
  现有配置。
- 密码使用 bcrypt（cost 12）存储；系统生成的初始密码只在创建/重置时展示一次，
  之后不可再次读取。
- 重置密码与封禁会立即吊销目标用户全部会话；修改密码保留当前会话、吊销其他会话。
- 身份绑定流程继续校验 state、PKCE、nonce；绑定不签发会话，不改变用户角色。
- 至少保留一个可登录超管的约束在服务端强制执行，不能只靠界面限制。
- 不新增 Cookie，不改变 CORS/CSRF 现状；审计日志记录账号创建、密码重置、角色变更、
  本地登录失败，均不含密码明文。

### N2 兼容性

- 数据库变更为增量迁移，现有用户、身份、站点、批注、审核数据保持不变。
- 升级后旧会话仍可用于站点访客接口，但不能访问管理 API；重新本地登录后恢复后台访问。
- SDK 与站点公共 API 的行为、请求/响应结构不变；本地账号不会出现在站点访客登录
  方式中。
- 既有本地超管引导（默认账号、环境变量指定、重置密码开关）保持可用。
- `SUPERADMIN_GITHUB_LOGINS` 不再被读取；即使环境变量仍存在也不导致启动失败。

### N3 可运维性

- 后台提供完整的账号生命周期操作：新建、为已有用户开通、重置密码、授予/撤销超管、
  站点管理员角色、绑定/解绑身份。
- CLI 密码重置覆盖任意本地管理员账号，用于忘记密码或超管自锁的离线恢复。
- 同步更新以下文档面：登录与身份、管理与账号 API、CLI 参考、部署配置、安全边界，
  以及提到「后台可用 GitHub/OIDC 登录」的快速开始与自托管说明。
- 不引入新的外部依赖或服务（如邮件服务、消息队列）。

### N4 性能与容量

- 会话来源随会话记录一同读取，不为每次鉴权增加额外查询。
- 管理员账号数量级很小，列表与操作不引入分页以外的新复杂度。
- 登录与鉴权路径保持常数级数据库访问。

### N5 可用性

- 登录、建号、重置、绑定失败的提示使用中文且可理解；生成密码弹窗支持复制，并明确
  「仅显示一次」。
- 登录表单保留用户名、当前密码、新密码的自动填充语义。
- 强制改密状态在界面上有明确提示，且无法绕过进入其他管理页面。

### N6 可测试性

- 覆盖正向与反向场景：本地登录、非本地会话拒绝、旧会话拒绝、最后超管保护、
  绑定冲突、重置后会话失效。
- 现有 Go 测试、管理后台类型检查与单元测试、SDK 测试全部保持通过。

## 不做的事

- 不为站点访客提供内置账号、注册、邮箱验证、找回密码邮件或验证码；访客登录仍只走
  站点 OIDC / 全局 GitHub。
- 不允许 OIDC/GitHub 作为后台登录方式，包括「绑定后作为备用登录」。
- 不做账号合并、身份转移、跨账号邮箱合并；绑定冲突只报错，不自动合并。
- 不做 MFA、TOTP、WebAuthn、密码历史、复杂度评分、定期过期。
- 不做用户删除或本地凭据删除；离职/停用沿用封禁，遗忘密码沿用超管重置或 CLI 重置。
- 不做管理员自助注册、自助修改用户名、自助找回密码。
- 不改变站点级 OIDC 提供商的配置模型；它们继续只服务站点访客登录与管理员身份绑定。
- 不做独立审计表、审计日志导出或告警系统；仅在应用日志中记录关键操作。
- 不保留旧后台 GitHub/OIDC 直登的过渡期兼容。
- 不改变 SDK 界面与服务端站点公共 API 的语义。

## 验收标准

### 后台登录与访问控制

- **AC1** 打开后台登录页只看到用户名/密码表单，不再出现 GitHub 或站点 OIDC 登录
  按钮；访问旧的后台外部登录地址不可用。
- **AC2** 错误密码与不存在的用户名返回同一错误提示；连续失败触发限流；被封禁账号
  登录被拒绝并提示封禁。
- **AC3** 用站点 OIDC 或 GitHub 访客登录得到的令牌调用任一管理 API 返回 403；
  同一令牌调用站点公共接口仍正常。
- **AC4** 升级前签发、非本地密码登录的旧会话调用管理 API 返回 403；改用本地密码
  重新登录后可正常访问。
- **AC5** 站点管理员用本地密码登录后只能访问被授予站点的管理功能；超管可访问全部
  站点。

### 管理员账号

- **AC6** 超管可新建管理员账号（用户名、显示名、初始密码、超管或站点管理员角色），
  新账号首次登录被强制改密。
- **AC7** 超管可为已有用户开通本地密码；开通后该用户的历史批注、审核记录与已绑定
  身份仍归属同一账号；对已有本地密码的用户重复开通报错。
- **AC8** 超管重置其他管理员密码后：旧密码失效、该用户全部会话立即失效、新密码
  登录后要求强制改密。
- **AC9** 撤销最后一个超管、封禁最后一个可登录超管均被拒绝；撤销或封禁其他超管
  正常生效。
- **AC10** 用户名重复（大小写不敏感）、用户名格式非法、密码过短时，创建或开通操作
  返回明确校验错误。

### 强制改密与会话

- **AC11** 强制改密状态下访问管理列表返回「必须修改密码」错误；改密成功后恢复访问；
  其他会话被吊销，当前会话保持有效。

### 身份绑定

- **AC12** 管理员可在账号设置页完成 GitHub 或站点 OIDC 绑定；回跳后显示新身份，
  不新增用户、不新增会话，且该身份不能用于后台登录。
- **AC13** 绑定已属于其他用户的身份返回冲突提示；解绑后该身份从列表消失；有本地
  密码的账号可解绑全部身份。
- **AC14** 绑定失败时回跳账号设置页并显示失败原因，不出现原始错误页。

### 移除外部直登与自动超管

- **AC15** 配置 `SUPERADMIN_GITHUB_LOGINS` 后，命中用户通过 GitHub 访客登录不再
  获得超管角色；按 GitHub 登录名提升超管的 CLI 能力不可用。

### 站点访客侧

- **AC16** SDK 登录面板仍只展示站点 OIDC / GitHub 入口；后台本地账号无法用于 SDK
  登录；访客批注与审核流程行为不变。

### 升级与 CLI

- **AC17** `zhupi admin password reset --username <任意本地管理员>` 可重置密码并
  成功登录；升级后未开通本地密码的管理员被拒绝进入后台，超管开通后恢复。
- **AC18** 迁移后现有用户、身份、站点、批注与审核数据完整；保留旧环境变量时服务
  正常启动。

### 质量与文档

- **AC19** `go vet ./...`、`go test ./...`、管理后台类型检查与单元测试、SDK 测试
  全部通过。
- **AC20** 认证、管理 API、CLI、部署配置与安全文档不再声称后台可用 GitHub/OIDC
  直登，且与实际行为一致。
- **AC21** 应用日志记录建号、密码重置、角色变更、本地登录失败，且不包含密码明文
  或哈希。
